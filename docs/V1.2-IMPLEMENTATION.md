## User-approved change of architecture

The original V1.2 plan listed Astro, but the first implementation preserved a Vite SPA due to existing traffic. The user explicitly approved proceeding with Astro despite the modest baseline. Therefore Vite's SPA entrypoint, Vite config and obsolete Vite-specific prerender task were removed. Astro now owns page URLs and SEO metadata. Older interactive diagnostics are reused as React islands instead of rewriting their complex browser tests immediately.

This is a genuine static Astro build; React is retained as the interaction library within islands.

## How static SEO works

- All pages receive HTML `<title>`, meta description, language and a canonical in `src/layouts/BaseLayout.astro`.
- First-language HTML content is generated at build time rather than injected by client-side Helmet.
- Old React SEO components suppress their duplicate runtime tags when embedded in Astro, so there is only one canonical.
- Four reciprocal English and pt-BR `hreflang` clusters are mapped only where the pages have equivalent scope.
- Sitemap contains 50 canonical URLs, preserves old important tool paths and omits fabricated `lastmod` dates.
- Custom `404.astro` avoids treating nonexistent URLs as a blank SPA route.
- New tool pages include real interactive React testing controls plus indexable instructions and limitations.

## Features and user safety

- Static full-screen colors, horizontal and vertical lines, grayscale and checkerboard test patterns.
- Manual marker positions (ratios of displayed viewport, not physical pixel coordinates); JSON user-check export.
- Static movable comparison patch. No high-frequency strobe control in the core dead-pixel test.
- Old report's fictitious certified health scores removed; exports state explicitly that observations are not certified.
- Browser `requestAnimationFrame` FPS != guaranteed hardware refresh Hz; CSS dimensions and DPR != native resolution or physical DPI.
- No claim that a browser can automatically locate or repair physical pixel defects.

## Build verification

GitHub Actions pipeline:

1. Node 22 install.
2. `npm run check:types` for React/TypeScript source.
3. `npm run build` creates sitemap first, generates Astro HTML and audits 20 priority routes.
4. Check English root, Brazilian content and important existing GSC routes.
5. Install Chromium and start `astro preview`.
6. Browser test of real pages, mobile responsive inspection, marking and existing tools. Reject duplicate canonical tags.

**Build success is not Cloudflare production verification.** CI output must be checked for the latest revision; do not reuse the earlier Vite CI result.

## Remaining manual / production gates

1. Cloudflare Pages preview URL: verify all built routes respond HTTP 200 and actual canonical origin remains correct.
2. Verify slash/no-slash 301 behavior for old `/tests/*` and new `/pt-br/*` URLs; update internal links and redirects if needed.
3. Compare browser screenshots and interaction on mobile Chrome, iOS Safari, macOS Safari and Firefox (Chromium CI alone is not full cross-browser coverage).
4. Test physical display patterns, fullscreen exit, multi-monitor scenarios and keyboard controls on real devices.
5. Verify `robots.txt`, `sitemap.xml`, meta tags and `hreflang` on actual Cloudflare response.
6. Separate preview indexing rules from production; do not let a staging hostname be indexed by accident.
7. Check content accuracy of historical blog articles and remove outdated or risky pressure/rapid-flicker repair advice where needed.
8. Assess page size, Core Web Vitals, accessibility and interaction performance from the actual deployment.
9. Monitor Search Console after merge, including legacy GSC URL coverage and the new Portuguese cluster.

## Known functional tradeoffs

- Some legacy tools are still hosted by the original React Router app **inside Astro islands**. Astro renders their entry URLs statically, but the legacy test UI needs JavaScript. This minimizes the risk of breaking working complex diagnostics.
- The former Vite PWA plugin is removed with the old bundler; offline installation behavior is not preserved until a separate Astro-compatible PWA implementation is explicitly validated.
- Local self-check JSON is not a certified test report.
- SEO performance, actual advertising income, search intent beyond the provided data, and Cloudflare production behavior are not guaranteed by passing CI.

Do not merge the draft PR or claim the live site has migrated solely because the Astro build succeeds.
