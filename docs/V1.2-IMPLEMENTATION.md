## SEO and rendering rules

- Keep current `.cc` host as canonical, because this is an existing site. The `.org` domain is a **separate competitor**.
- New landing pages have per-page title, description, H1, FAQ prose, functional test controls and internal links.
- `scripts/prerender-pages.ts` writes dedicated `dist/<new path>/index.html` pages with initial indexable HTML while keeping original routes intact.
- `scripts/generate-sitemap.ts` includes the existing menu/blog URLs and new pages, deduplicates, and omits fictitious per-build `lastmod` values.
- Only four genuinely equivalent pairs are proposed for reciprocal en / pt-BR `hreflang`: core test, laptop/notebook, static stuck-pixel guide, dead-pixel definition.
- English generic phone and Portuguese iPhone pages **are not** reciprocal alternates.
- `/tests/dead-pixel` remains reachable but canonicalizes to `/` and is removed from sitemap to avoid internal duplication.

## Functional safety and honesty

- New pages contain static manual patterns only; marks are local page state.
- Suspect spots store viewport ratios and observable colors, **not physical pixel coordinates**.
- JSON export reports manual self-observation and cannot be treated as certified hardware evidence.
- The legacy report dashboard no longer exports a fake guaranteed screen health grade or certification.
- Home test removes the high-frequency strobe / animated noise control.
- Header uses FPS and DPR labels, rather than pretending those indicate true hardware refresh Hz or physical DPI.

## Release gates

**Automated (CI):** TypeScript compile, Vite build, sitemap generation, static page output, retention of key GSC paths in sitemap.

**Still required before production:**

1. Confirm Cloudflare preview deployment of the PR and test real external URLs. No current preview deployment has been verified.
2. Check original `/tests/refresh-rate`, `/tests/local-dimming`, `/tests/color-gradient`, `/tests/audio-sync` and `/` respond with HTTP 200 and retain correct canonical.
3. New English and Brazilian landing URLs must respond HTTP 200 and contain correct static Title, H1, canonical, language and relevant unique content.
4. Verify both directions of the four `hreflang` pairs and actual route equivalence; exclude missing locales.
5. Test fullscreen API and fallback on Chrome, Firefox, Safari and mobile; check ESC, swipe, key controls, marking, undo and JSON download.
6. Check contrast patterns and the screenshot-to-hardware warning; use a physical display for final observation.
7. Confirm there are no high-frequency strobe controls in the production bundles.
8. Test ad placement, mobile accessibility, no overlay blocking critical buttons and no cross-language boilerplate.
9. Re-measure original ranking pages in GSC after rollout; rollback if widespread 404/canonical issues emerge.
10. Verify hosting's directory-index trailing-slash behavior **before** merging. New pages intentionally use trailing slashes; old GSC URLs must not be redirected unexpectedly.

**Unverified status:** CI completion does not prove any of these real-browser, production, device or commercial checks.
