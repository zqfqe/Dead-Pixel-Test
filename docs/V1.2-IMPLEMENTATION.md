## User-approved change of architecture

The original V1.2 plan listed Astro, but the first implementation preserved a Vite SPA due to existing traffic. The user explicitly approved proceeding with Astro despite the modest baseline. Therefore Vite's SPA entrypoint, Vite config and obsolete Vite-specific prerender task were removed. Astro now owns page URLs and SEO metadata. Older interactive diagnostics are reused as React islands instead of rewriting their complex browser tests immediately.

This is a genuine static Astro build; React is retained as the interaction library within islands.

## How static SEO works

- All pages receive HTML `<title>`, meta description, language and a canonical in `src/layouts/BaseLayout.astro`.
- First-language HTML content is generated at build time rather than injected by client-side Helmet.
- Old React SEO components suppress their duplicate runtime tags when embedded in Astro, so there is only one canonical.
- Four reciprocal English and pt-BR `hreflang` clusters are mapped only where the pages have equivalent scope.
- With `PUBLIC_SITE_URL`, Sitemap contains only index-approved canonical URLs and omits fabricated `lastmod` dates. Without a configured origin, the sitemap is empty and every page is `noindex,nofollow`.
- Custom `404.astro` avoids treating nonexistent URLs as a blank SPA route.
- New tool pages include real interactive React testing controls plus indexable instructions and limitations.

## Features and user safety

- Static full-screen colors, horizontal and vertical lines, grayscale and checkerboard test patterns.
- Manual marker positions (ratios of displayed viewport, not physical pixel coordinates); JSON user-check export.
- Static movable comparison patch. No high-frequency strobe control in the core dead-pixel test.
- Old report's fictitious certified health scores removed; exports state explicitly that observations are not certified.
- Browser `requestAnimationFrame` FPS != guaranteed hardware refresh Hz; CSS dimensions and DPR != native resolution or physical DPI.
- No claim that a browser can automatically locate or repair physical pixel defects.

## Known functional tradeoffs

- Some legacy tools are still hosted by the original React Router app **inside Astro islands**. Astro renders their entry URLs statically, but the legacy test UI needs JavaScript. This minimizes the risk of breaking working complex diagnostics.
- The former Vite PWA plugin is removed with the old bundler; offline installation behavior is not preserved until a separate Astro-compatible PWA implementation is explicitly validated. Domainless builds now deliberately stay noindex and publish no guessed canonical or sitemap.
- Local self-check JSON is not a certified test report.
- SEO performance, actual advertising income, search intent beyond the provided data, and Cloudflare production behavior are not guaranteed by passing CI.

Do not merge the draft PR or claim the live site has migrated solely because the Astro build succeeds.

## Additional implementation completed after the initial Astro migration

- Removed the unverified hardcoded public origin. `PUBLIC_SITE_URL` is now the only source of canonical origin. With no real domain configured, the build emits `noindex,nofollow`, no canonical/hreflang, an empty sitemap and a robots file without a guessed Sitemap URL.

- The core pixel workflow is exactly eight static colors in the planned order. Gray, gray steps, near-black, near-white, line, checkerboard and gradient patterns are additional modes, not extra steps in the core eight-color test.
- Marker records now include observation category, notes, viewport ratios, CSS viewport dimensions, DPR, orientation and the colors on which a spot was rechecked. JSON and printable HTML exports identify the record as user-observed, not certified.
- Fullscreen refusal has an on-page overlay fallback; Escape exits, keyboard focus is trapped while open and focus returns to the start button on exit.
- Resolution checker now reports screen/available dimensions, browser and visual viewport, DPR, color/pixel depth and orientation, explicitly as browser-reported CSS metrics rather than guaranteed panel-native resolution.
- Latest CI evidence: TypeScript, domainless noindex build audit, configured-origin build audit and Chromium checks. Real device/browser-family validation, custom-domain HTTP, Search Console and advertising remain separate gates.

### Image retention and OLED burn-in
- Retention test now starts on neutral gray and uses brief uniform fields (near-black, near-white, white, black and RGB) rather than unrelated checkerboard/gradient patterns.
- Copy distinguishes temporary image retention from permanent OLED burn-in and states that the browser cannot diagnose, quantify or repair either.
- The separate OLED pattern demo no longer claims to fix burn-in or stuck pixels. Noise is generated once rather than flashing new noise every frame; color transitions are slower; session duration is capped at five minutes with a two-minute default.
- Safety text tells visitors to stop if moving/changing patterns cause discomfort and to follow manufacturer panel-care guidance.

### Screen-line inspection
- Dedicated 10-step line mode: five solid fields, coarse horizontal/vertical stripes, fine horizontal/vertical CSS-pixel lines, and a grid.
- UI and page copy state that fine lines are CSS pixels, not guaranteed physical panel pixels; the test documents symptoms but cannot identify the failed component.

### Browser verification
- Added checks for the exact retention and line pattern sequences.
- Added privacy/contact policy checks, same-origin request audit, webcam local-download test and local image object-URL test.
